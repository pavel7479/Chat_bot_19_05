СХЕМА ПРОЕКТА Chat_bot

1. Общая идея
Проект устроен как многошаговый чат-бот для продаж и поддержки каталогов/подписок.
Он не отвечает одним куском "из модели", а проходит через несколько слоёв:
- понимает смысл реплики
- определяет тему и сценарий
- собирает факты и цены
- строит детерминированный ответ
- при необходимости сверяет LLM-ответ с правилами
- обновляет состояние диалога
- пишет подробную телеметрию

2. Верхний уровень проекта
- config.yaml
  Главный конфиг приложения: провайдер LLM, пути к prompt/yaml-файлам, retrieval, логирование, API.

- prompts/
  Prompt-файлы для генерации ответа и связанных задач.

- knowledge_base/
  Сырая база знаний в текстовом виде.

- logs/
  Технические логи бота, тестов и разборов диалогов.

- src/
  Основной код приложения.

- the_First_Agent/
  Логика первого агента: Agent Zero, shortlist, topic classifier, follow-up, context signals.

- tests/
  Автотесты, снапшоты, служебные файлы и stage-based наборы тестов.

3. Точка входа и сборка приложения
Файл: src/main.py

Ключевые функции:
- build_app(...)
  Собирает весь бот из компонентов.
- create_app(...)
  Создаёт FastAPI-приложение.
- run_cli()
  Запуск в терминале.
- run_api()
  Запуск HTTP API.

Что делает build_app:
- создаёт LLM provider
- поднимает первый агент
- поднимает второй агент
- подключает retrieval
- подключает роутер, state update, telemetry
- собирает ChatBotOrchestrator

4. Главный оркестратор
Файл: src/app/chatbot.py
Класс: ChatBotOrchestrator

Человеческим языком:
Это главный диспетчер всего диалога.
Он получает сообщение пользователя и дальше координирует весь pipeline.

Что делает:
- сохраняет сообщение в историю
- достаёт состояние сессии
- запускает извлечение слотов
- вызывает Agent Zero / IntentAgent
- вызывает DialogActRouter, если нужен жёсткий маршрут
- строит response plan
- достаёт знания и бренды
- собирает answer block
- вызывает ResponseAgent для финального ответа
- применяет post-processing и greeting policy
- обновляет state после классификации и после ответа
- пишет debug/telemetry

5. Первый агент: понимание смысла и выбор темы

5.1. IntentAgent
Файл: src/agents/intent_agent.py
Класс: IntentAgent

Роль:
Это координатор первого агента.
Он не просто спрашивает модель "что хотел пользователь", а собирает вокруг этого много контекста.

Что делает:
- получает результат Agent Zero
- строит context signals
- считает follow-up
- строит shortlist возможных тем
- вызывает TopicClassifier
- применяет SemanticCompatibilityValidator
- кладёт semantic_frame в diagnostics и state

Именно здесь сейчас живёт логика:
- classifier path
- dialog_act path
- semantic compatibility stage

5.2. Agent Zero
Папка: the_First_Agent/Agent_Zero/

Файлы и классы:
- context_understanding_agent.py -> ContextUnderstandingAgent
  Делает запрос к модели, чтобы получить gist/meaning/semantic_frame.

- parser.py -> ContextUnderstandingParser
  Разбирает ответ модели в JSON, валидирует и делает fallback.

- models.py
  Содержит Pydantic-схемы и ContextUnderstandingResult.

Человеческим языком:
Agent Zero отвечает на вопрос:
"Что сейчас по смыслу имеет в виду пользователь?"
Он не выбирает финальный ответ и не выбирает факт из базы знаний.

5.3. TopicClassifier
Файл: the_First_Agent/orchestrator/topic_classifier.py
Класс: TopicClassifier

Роль:
Берёт shortlist допустимых тем и просит модель выбрать одну или две темы в нужном JSON-формате.

5.4. TopicShortlistBuilder
Файл: the_First_Agent/catalog/topic_shortlist_builder.py
Класс: TopicShortlistBuilder

Роль:
Сужает пространство выбора перед classifier.
Использует:
- слова из запроса
- смысловые сигналы
- брендовые совпадения
- continuity/follow-up

5.5. TopicCatalog
Файл: the_First_Agent/catalog/topic_catalog.py
Класс: TopicCatalog

Роль:
Читает YAML с описаниями тем/intents и превращает их в удобный каталог для prompt и shortlist.

5.6. ContextSignalExtractor
Файл: the_First_Agent/context/context_signal_extractor.py
Класс: ContextSignalExtractor

Роль:
Извлекает сигналы вроде:
- pricing
- purchase
- support
- manager
- company_services
по декларативным правилам из YAML.

5.7. FollowupResolver
Файл: the_First_Agent/followup/followup_resolver.py
Класс: FollowupResolver

Роль:
Определяет, является ли текущая реплика продолжением предыдущего сценария.
Например:
- "да"
- "подскажи"
- "а остальные"
- номер телефона после просьбы дать контакт

6. Semantic compatibility
Файл: src/intents/semantic_compatibility_validator.py
Класс: SemanticCompatibilityValidator

Роль:
Проверяет, не конфликтует ли topic classifier с SemanticFrame.

Пример:
- SemanticFrame говорит: пользователь выбирает каталог
- classifier говорит: tis_tariffs
- validator может сказать: это конфликт, лучше заменить на specific_brand_check

Что умеет:
- совместимо / несовместимо
- severity:
  - HARD_CONFLICT
  - SOFT_CONFLICT
  - WARNING
- override по shortlist
- fallback в безопасную тему, если совместимой темы нет

7. Жёсткий роутинг и сценарные переключения
Файл: src/app/dialog_act_router.py
Класс: DialogActRouter

Роль:
Это отдельный слой для жёстких протокольных или специальных случаев.
Например:
- greeting
- nonsense
- часть follow-up сценариев
- некоторые сценарные jump-ы

Он возвращает DialogActDecision.

9. Второй агент: планирование и ответ

9.1. ResponsePlanner
Файл: src/agents/response_planner.py
Классы:
- ResponsePlan
- ResponsePlanner

Роль:
Превращает topic classification в конкретный план ответа.

Что выбирает:
- primary_action
- primary_topic
- secondary_topic
- обязательные факты
- обязательные price blocks
- locked action или нет

Человеческим языком:
Это мозг второго шага: он решает не "что понял пользователь", а "какой ответный сценарий мы должны строить".

9.2. ResponseAgent
Файл: src/agents/response_agent.py
Класс: ResponseAgent

Роль:
Запускает второй агент целиком.

Что делает:
- получает ResponsePlan
- переводит state snapshot в ResponseState
- вызывает AnswerSynthesisService
- получает финальный BotResponse

9.3. AnswerSynthesisService
Файл: src/agents/response_services/pipeline_services.py
Класс: AnswerSynthesisService

Роль:
Это центральный слой выбора финального текста ответа.

Что делает:
- строит prompt для LLM
- собирает deterministic answer
- при необходимости получает ответ от модели
- проверяет action compatibility
- проверяет mandatory meaning
- выбирает источник финального ответа:
  - llm
  - deterministic
  - fallback
  - safe_default

9.4. GroundedAnswerComposer
Файл: src/agents/response_services/pipeline_services.py
Класс: GroundedAnswerComposer

Роль:
Собирает ответ из уже подготовленного контекста и фактов.

9.5. ResponseModelFactory
Файл: src/agents/response_services/pipeline_services.py
Класс: ResponseModelFactory

Роль:
Собирает финальный BotResponse из текста, action, evidence и trace.

21. Как проект работает в одном предложении
Пользователь пишет сообщение -> бот понимает смысл через Agent Zero -> classifier и compatibility layer выбирают тему -> planner выбирает action -> knowledge/pricing слои собирают контекст -> второй агент формирует безопасный финальный ответ -> state и логи обновляются.
